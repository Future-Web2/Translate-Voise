# Telegram: речь → текст → узбекский

Закрытый Telegram-бот для голосовых сообщений и видеокружков. Распознаёт речь локально на CPU, сохраняет исходные языки в расшифровке и отправляет ниже перевод на узбекский **латиницей**. В одном сообщении могут встречаться узбекский, английский и русский. Отдельные текстовые вопросы обрабатывает io.net.

## Что реализовано

- Голосовые `voice` и круглые видео `video_note`; FFmpeg извлекает аудио и приводит его к mono 16 kHz WAV.
- `faster-whisper`, CPU `int8`, определение языка по сегментам, VAD и отключённое переносимое между сегментами текстовое условие для уменьшения повторов.
- По умолчанию `large-v3`: приоритет качества. Модель настраивается без изменения кода.
- Исходная расшифровка сохраняется без «исправления» текстовой LLM. Сомнительные сегменты отмечаются с временными интервалами.
- io.net переводит исходный текст на узбекский. Для ответов на вопросы предусмотрен **отдельный ключ и модель**.
- Закрытый доступ по Telegram **user ID**, только личные чаты. Пустой список не открывает доступ всем: доступна только `/id`.
- Одна очередь, одно распознавание одновременно, ограничение размера/длительности/числа запросов. Это предотвращает одновременную загрузку нескольких больших моделей.
- Длинные ответы разбиваются; очень длинный полный результат отправляется UTF-8 `.txt` файлом.
- Если io.net недоступен, успешная расшифровка всё равно отправляется.
- Ограниченное по времени распознавание в отдельном переиспользуемом процессе; процесс завершается при таймауте и выключении. Временные аудио удаляются.
- Dockerfile, закреплённые зависимости, Railway-конфигурация, `/health` и CI.

Это готовая к настройке реализация, но реальная точность и доступ к сервисам должны быть проверены с вашими ключами и записями. Не проводились реальные вызовы Telegram/io.net, загрузка `large-v3` и запуск в Railway.

## Команды

| Команда / сообщение | Действие |
| --- | --- |
| Голосовое или кружок | Исходная расшифровка, ниже узбекский перевод |
| `/ask Почему…` | Отдельный ответ AI |
| Обычный текст | Также отдельный вопрос AI |
| `/translate текст` | Перевод текста на узбекский латиницей |
| `/id` | Ваш Telegram user ID; работает до выдачи доступа |
| `/status` | Очередь и состояние распознавания |
| `/start`, `/help` | Инструкция и сведения об обработке данных |

Бот не хранит историю вопросов. Каждое сообщение — отдельный запрос. Команда `/ask` не получает автоматически контекст ранее отправленной записи.

## Ключи и закрытый доступ

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Получите ключи в [io.net Intelligence](https://ai.io.net/). Один — для перевода, другой — для вопросов. Укажите текущие модели из вашего каталога.
3. Передайте секреты через Railway Variables или локальный `.env`; не публикуйте их в Git и не вставляйте в исходный код.
4. Добавьте разрешённые ID в `ALLOWED_USER_IDS`, например `123456789,987654321`. Нужны ID **пользователей**, не username и не ID групп.
5. Если свой ID неизвестен, запустите бот с пустым `ALLOWED_USER_IDS`, отправьте ему `/id`, затем добавьте ID и перезапустите сервис. Другие операции в этот момент закрыты.

io.net использует OpenAI-совместимые `/chat/completions` и `/models`. Точные доступные модели и бесплатный объём зависят от текущего аккаунта; отдельные ключи **не увеличивают** общий лимит аккаунта. Не обещаем постоянно бесплатный API или конкретное число токенов. См. [документацию API](https://io.net/docs/reference/ai-models/get-started-with-io-intelligence-api) и [правила кредитов](https://io.net/docs/guides/payment/io-intelligence-payments).

После заполнения `.env` модели можно посмотреть командой:

```powershell
.venv\Scripts\python.exe -m voicebot --models
```

Каталог поддерживает старую форму `id` и новую `name/model_id`, а также пагинацию. Значение `meta-llama/Llama-3.3-70B-Instruct` в примере взято из документации io.net; его доступность для вашего ключа ещё не проверена. В качестве стартовой модели перевода можно использовать доступную в вашем аккаунте многоязычную instruct-модель и сравнить на ваших записях.

## Railway

1. Загрузите проект в свой GitHub-репозиторий. В Railway создайте сервис из этого репозитория; сборка использует корневой `Dockerfile` и `railway.json`.
2. **Обязательно добавьте Volume с Mount Path `/data`.** Кэш модели будет в `/data/models`. Размер тома должен вмещать модель и запас; для `large-v3` начните с 6 GB диска и проверьте фактическое использование.
3. Добавьте Variables:

   ```dotenv
   TELEGRAM_BOT_TOKEN=<из BotFather>
   IO_TRANSLATION_API_KEY=<ключ для перевода>
   IO_QA_API_KEY=<отдельный ключ для вопросов>
   IO_TRANSLATION_MODEL=<доступный ID модели>
   IO_QA_MODEL=<доступный ID модели>
   ALLOWED_USER_IDS=<ваш Telegram user ID>
   WHISPER_MODEL=large-v3
   WHISPER_CPU_THREADS=2
   MODEL_CACHE_DIR=/data/models
   RAILWAY_DEPLOYMENT_OVERLAP_SECONDS=0
   RAILWAY_DEPLOYMENT_DRAINING_SECONDS=30
   ```

4. Для `large-v3` на CPU начните примерно с **6 GB RAM и 2–4 vCPU** и измерьте работу. Это инженерный запас, не измеренный минимум для Railway и не гарантия скорости. Если лимиты тарифа меньше — поставьте `WHISPER_MODEL=small` и выделите около 2 GB RAM; экономия может снизить точность узбекской речи. `medium` — промежуточный вариант. Не используйте `.en` и английские distil-модели.
5. Оставьте **одну реплику**, выключите Serverless/засыпание сервиса: бот использует постоянный long polling. Остановите локальную копию с тем же токеном. Не задавайте отдельный Start Command — Docker ENTRYPOINT уже запускает бот. Railway передаёт `PORT`, приложение слушает `0.0.0.0`.
6. Healthcheck Path — `/health` (уже в `railway.json`). Публичный домен для Telegram polling не обязателен; можно создать его для ручной проверки `/health`.
7. После запуска отправьте `/start`, короткое голосовое и кружок. Первая запись загружает модель: несколько минут или больше при медленной сети. Следующие записи используют модель в памяти. После перезапуска модель загружается с Volume, без повторного скачивания.

Пример `/health`: `{"status":"ok","asr":"cold"}` означает, что бот готов принимать запросы, но модель ещё не загружена. Состояния распознавания: `cold`, `working`, `ready`. Здоровье endpoint проверяет рабочую задачу, а не качество ASR или баланс io.net. Railway проверяет endpoint при развёртывании; это не постоянный мониторинг. См. [Railway healthchecks](https://docs.railway.com/deployments/healthchecks).

Volume нужен и для кэша, и для последовательного запуска версий при деплое. Одна реплика сама по себе не исключает краткого пересечения старой и новой версии; для одного токена Telegram допускается один polling-процесс. Подключённый Volume исключает одновременные активные deployments с этим томом, ценой короткого перерыва. См. [aiogram long polling](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html), [Railway Volume/healthcheck behavior](https://docs.railway.com/deployments/healthchecks) и [завершение deployments](https://docs.railway.com/deployments/deployment-teardown).

Очередь хранится в памяти. Незавершённый запрос при рестарте может потеряться — отправьте запись повторно. Не включайте несколько реплик без перехода на webhook и внешнюю очередь. Railway CPU/RAM/Volume оплачиваются по правилам хостинга, даже когда отдельный STT API не используется.

## Локальный запуск (Windows)

Нужны Python **3.11–3.13** (рекомендуется 3.12) и FFmpeg/ffprobe в `PATH`. Установленные версии зависимостей закреплены в `requirements.lock`.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock
.venv\Scripts\python.exe -m pip install --no-deps -e .
Copy-Item .env.example .env
```

Заполните `.env`. Для Windows измените `MODEL_CACHE_DIR` с Railway-пути на `data/models`.

```powershell
.venv\Scripts\python.exe -m voicebot
```

Docker локально:

```powershell
docker build -t uzbek-voicebot .
docker run --rm --env-file .env -p 8080:8080 -v voicebot-models:/data -e MODEL_CACHE_DIR=/data/models uzbek-voicebot
```

Для разработки:

```powershell
.venv\Scripts\python.exe -m pip install -e '.[dev]'
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check src tests docker-entrypoint.py
```

CI выполняет тесты на Linux с FFmpeg и собирает Docker. Он начнёт работать после загрузки проекта в GitHub.

## Точность и смешанная речь

Whisper поддерживает узбекский, английский и русский. `language=None`, `multilingual=True` включает определение языка по сегментам; переключение внутри одной фразы всё равно может приводить к ошибкам. `task=transcribe` сохраняет исходные языки; узбекский перевод выполняет io.net. См. [faster-whisper](https://github.com/SYSTRAN/faster-whisper) и [описание Whisper large-v3](https://huggingface.co/openai/whisper-large-v3).

Слабая уверенность отмечается, если `avg_logprob < -0.85` или хотя бы у одного слова `probability < 0.35`. Это эвристика, а не откалиброванная вероятность правильности: часть ошибок не будет отмечена, а часть отмеченных слов окажется правильной. Текст модели внутри метки сохраняется; бот не заявляет, что смог восстановить неразборчивое слово.

Для имён и терминов настройте короткий `ASR_GLOSSARY`, например `Toshkent, Samarqand, Kubernetes, Ali`. Это подсказки ASR, а не гарантия. `ASR_LANGUAGE=auto` — рекомендуемый режим для смешанной речи. `uz`, `ru`, `en` можно принудительно задать для одноязычных записей, если автоопределение ошибается.

Проверка перед использованием:

| Запись | Проверить |
| --- | --- |
| Чистый узбекский | Имена, окончания, латиница перевода |
| Узбекский + английский в одной фразе | Исходные английские термины и полный смысл |
| Узбекский + русский | Смена языка и сохранение чисел |
| Кружок | Наличие звука и та же структура результата |
| Тишина / сильный шум | Отсутствие уверенно заявленной выдуманной речи |
| Плохой интернет / исчерпан io.net | Расшифровка возвращается даже без перевода |
| Неавторизованный пользователь | Нет распознавания и платных/квотируемых AI вызовов |

Реальную точность нужно оценить на 10–20 ваших записей с вручную проверенным текстом. Голос с действительно неразборчивыми словами нельзя гарантированно восстановить. Условие сохранять метки и игнорировать команды внутри транскрипта передаётся текстовой модели, но следование LLM этим инструкциям также требует проверки.

## Лимиты и данные

- По умолчанию не более 5 минут / 20 MiB на запись; Telegram облачный Bot API документирует предел скачивания 20 MB, для превышения требуется отдельный Bot API server. См. [Telegram Bots FAQ](https://core.telegram.org/bots/faq).
- Локальное аудио остаётся только на время обработки. В io.net передаётся **текст**, аудио туда не отправляется. Текст вопросов также отправляется в io.net. Сам Telegram хранит переписку по своим правилам.
- Содержимое сообщений, URL с токенами и сырые ошибки провайдеров не записываются приложением в логи. В io.net не передаются Telegram ID.
- Timeout ASR включает первоначальное скачивание и загрузку модели. При превышении процесс прекращается; следующая запись запускает новый процесс и использует доступный кэш.
- `/status` и `/id` продолжают работать во время распознавания. Другие задачи выполняются последовательно; один пользователь может иметь только один незавершённый запрос.
- Изменения переменных окружения требуют перезапуска сервиса. После смены модели первый запрос загрузит новую модель в тот же кэш.

## Файлы

- `src/voicebot/bot.py`: доступ, команды, очередь, скачивание и отправка результатов.
- `media.py`: извлечение аудио, размер, длительность, очистка и FFmpeg.
- `asr.py` / `asr_worker.py`: управляемый CPU-процесс распознавания.
- `ai.py`: io.net, отдельные ключи, повторные попытки, перевод и вопросы.
- `text.py`: сохранение исходного текста, метки и разделение ответов.
- `config.py`: проверяемые настройки из окружения.
- `.env.example`: полный шаблон настроек без секретов.
- `Dockerfile`, `docker-entrypoint.py`, `railway.json`: развёртывание.

В проект намеренно не включены реальные токены, ключи, пользовательские аудио и история сообщений.
